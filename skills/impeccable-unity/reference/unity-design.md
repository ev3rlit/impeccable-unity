# Design flow and mode-specific judgment

Read design-principles.md for authority and design-policy.md before edits. Preserve the original category-default conditions; the shared floor never chooses the art direction. A project brief can earn many common treatments, while the explicit no-exception eyebrow/kicker ban and nested-card ban retain their strength. A genuine neobrutalist world can justify its hard-offset shadows; invented technical costumes cannot. Ornament, geometric diagrams and actual illustration are different media, regardless of renderer.

## New work

Inspect current screens, code, tokens and assets first. A local addition inherits the screen's established identity; no concept tournament or DESIGN.md replacement. A new screen in an established world keeps the world and explores structure only when materially open. A redesign replaces composition/visual world while preserving truth, capabilities and binding commitments. Confirm unsettled material choices with the human; do not ask again for established decisions or require CSS values.

For an open whole screen, derive five to seven different content/task-based structures. For a new/replacement identity derive seven concrete visual systems from the audience's cultural world spanning at least three material families; exclude the category's default and predictable opposite. A literal reading of the product's name gets at most one candidate. For Operate/Read, an instrument/terminal costume does not become a world just because users operate instruments.

Expose a meaningful choice rather than silently picking the first plausible template. Select a lead without always favoring the first item (use an available random choice if needed), then compare plausible challengers on audience identification and product clarity. A challenger must supply a coherent visual grammar while real product facts remain unchanged. Explain which wins, stays competitive or is declined; borrow system discipline from a declined direction, not isolated decorative motifs. Present the lead and genuine alternatives with structure, first view, interaction, cross-screen reach and honest costs. Native screenshots, supplied images or concise wireframes may illustrate the choice; no local web decision page is required.

After the necessary decision is settled, implement the authorized screen using the shared Unity references and craft floor. Keep a needed direction contract in an existing development-only screen brief (thesis, world, story, first view, form and finish), never player-facing assets. Document durable system changes only when authorized. For narrow requests already specified, proceed from their given decisions rather than adding a workshop. shape stops before persistence/implementation, as its playbook specifies.

## Operate and Read

Familiarity can be a feature. Product slop is strangeness without purpose: over-decorated buttons, mismatched controls, gratuitous motion, display fonts in labels and invented affordances for standard tasks. Prefer precise consistent behavior. A single well-tuned font family is often right; system fonts and familiar sans defaults are explicitly allowed for task UI. Do not apply own-world display-face restrictions to every HUD label. Use a stable role scale, often 1.125–1.2 between steps; adapt structure rather than fluidly shrinking every label. Map scale to supported panel/font units, not web rem/clamp output. Prose still needs readable measure; dense data can be denser.

Color defaults to restraint, with accents serving primary actions, selection and state. A particular surface can earn a committed color world. Keep a semantic vocabulary and quiet secondary surface layers. Never convey state by color alone. Every applicable control state needs a deliberate appearance: default, hover, focus, active, disabled, loading and error. Use honest loading skeletons where they fit real content, informative empty states and consistent affordances. No fake delay or progress.

Overlays must escape clipping: use the project's overlay root, visual-tree ordering, host sort order or version-supported popup controls, not web fixed/portal APIs. Keep focus and input ownership. Most task transitions are brief (often 150–250ms), convey feedback/continuity and preserve repeated-use speed. No gratuitous page-load sequence. Standard navigation, density and consistency are permissions, not failures to be disguised with decoration.

## Persuade and Experience

When the brief calls for an expressive world, commit to a coherent one: subject-specific imagery, hierarchy, a meaningful first view and intentional pacing. Do not invent proof or add features to decorate empty space. Deliver needed assets where authorized, preserving licensing/provenance using project conventions; prefer existing assets before new dependencies. Typography pairing, palette intensity and material expression come from the chosen world, not a universal style preset. Choose one focal moment rather than effects on every control. Runtime frame/input constraints and design prohibitions still apply.
